# ADR-0002：P1 依赖候选、构建证据与框架切换

日期：2026-10-15。状态：accepted（采用候选及验证准则；不是兼容性验收通过）；范围：XIAO-34/P1及P2的E1。运行验证状态：未执行。

## 问题与当前规模

P1 要交付可编译契约、样例、双角色启动及自动门禁；首个业务纵切是单 Agent 网页报告。主方案0.3已比较 Spring AI 与 Alibaba，当前没有复杂图需求或已完成的构建/恢复实验，不需要再次叠加编排框架。

## 决定

| 项目 | P1 采用值 / 约束 |
| --- | --- |
| Java | JDK 21，不启用 preview；compiler release、Enforcer范围、本地与CI工具链一致 |
| Maven | Wrapper 固定 `3.9.9`，固定分发校验；不依赖运行机默认 Maven |
| Boot | `org.springframework.boot:spring-boot-starter-parent:4.1.1` |
| AI | 导入 `org.springframework.ai:spring-ai-bom:2.0.1`；所需 Spring AI 模块不各自漂移版本 |
| 运行链 | 一个 `ToolCallingAdvisor` 工具循环；`ToolCallback` 只适配并委托内核调用网关；禁止叠第二个自动工具循环 |
| 构建门禁 | Spotless/Google Java Format、SpotBugs、Enforcer、ArchUnit、Surefire、Failsafe；与所选 JDK/依赖实际兼容后固定准确版本 |
| Schema | 真正支持2020-12的服务端 validator，显式配置格式校验和本地引用边界；固定准确制品/版本并验证与Boot所选JSON依赖兼容，不因模型只支持子集而削弱服务端定义 |

Boot parent 管理其依赖，Spring AI BOM 管理 AI 依赖；这是同一主选技术栈的两层依赖管理，不禁止正常的父POM/BOM组合。禁止的是同时引入 Spring AI 1.x/2.x 或 Alibaba 备选编排链。版本冲突应按实际 artifact、路径与官方兼容证据处理，不全局关闭 convergence，也不靠手工强制升级一串传递依赖凑绿。

框架依据来自已验收主方案§3/§12：Spring AI `v2.0.1` 固定源码 `c9107fdac0a6c88489c08bb88abcee74c146981d` 的POM，及Alibaba `1.1.2.2` 固定源码 `7405a7dc0d66d582ec79430af6e24d259d5ca6ea` 的POM。本轮引用已验收静态证据，没有重新访问这些远端，也没有本机依赖解析结果。开始实际采用时仍须复核制品可获得性、维护/安全状态，记录确切依据。

P1 默认验证可使用受控模型HTTP fixture、受控网页与真实 Java worker 进程；不依赖收费模型/搜索凭据。fixture不等于真实模型或网页业务验收。未启用的模型业务不应仅为骨架 readiness 强制请求真实模型；当前角色声明为必需的DB、存储、worker资源则必须真实具备，缺失必须失败。

只添加当前职责确需的starter与库，不默认引入向量库、Graph、MCP服务器、消息broker或全量工具闭包。数据库/驱动、存储与隔离运行时须根据明确绑定的独立资源确定，不能套用其他项目配置；后端在实际实现前记录具体版本/范围，缺相应资源时如实阻塞对应验证。构建插件和validator准确版本属于可由后端完成的兼容性固定，不要求等待架构师逐个批准。

## 验证和正式锁定

后端可先开文档或骨架草案PR；P1骨架验收前，PR至少给出：

1. 固定提交、`java -version`、Wrapper版本、有效POM及完整依赖树；制品/插件准确版本可追溯，保留原始命令与退出码。
2. 干净环境完整 `./mvnw -B -ntp verify`（Windows为 `mvnw.cmd`）通过，包括绑定的格式、静态、收敛、真实类架构扫描、单元/契约、当前阶段必要的真实DB/存储/worker集成和打包/启动。记录实际测试数量、断言及资源清理；不得静默跳过或用零测试通过。
3. 违规依赖、格式、重复插件ID/坏Schema、缺必需资源的负向构建/运行确实失败；修复后针对性复验。
4. 控制与worker角色分别按自身职责验证readiness；网络、模型、序列化与实际validator依赖兼容问题逐项说明，不能只证明POM能解析。

P1构建成立后可称“该固定提交的骨架兼容性通过”。框架运行链的正式确定还取决于P2/E1：在每个持久边界注入崩溃，证明模型请求/响应、工具意图/结果可恢复，已成功工具不重放；memory或一次正常对话不替代恢复证据。P2/E1与P3真实模型/搜索、业务和安全验收分别记录，不能将后期通过冒称本轮已取得。

## 备选与切换条件

备选整套为基线的 JDK17 / Boot3.5.8 / Spring AI1.1.2 / Alibaba1.1.2.2，采用一条Graph/Agent运行链；不与主选BOM或循环同时存在。切换意味着重新核对工具链、安全维护状态、适配器、依赖闭包与门禁，不能只替换一个版本号。

仅在以下证据之一成立时，由架构记录替代ADR并组织重验：

- 主选存在可复现且经定位不能合理修正的构建/兼容阻断，或实施前维护/安全核验排除该组合；
- P2/E1证明主选的扩展点不能满足首期必要持久边界；
- 新的真实业务确需复杂图或人工中断，备选收益和迁移代价有具体依据。

GitHub访问超时、缓存缺失、仓库权限或制品仓库不可达属于环境/访问问题，不能直接证明框架不兼容或触发静默降级。暂未验证的备选不因主选受阻就自动成为已通过方案。后端回传脱敏命令、首个失败层、依赖路径与最小复现；架构据此取舍。

本轮不部署、不调整共享服务、不运行收费API；后端仍是唯一仓库写入者。
