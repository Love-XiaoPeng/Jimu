# Canonical history policy schema proof

This checkpoint supersedes only the per-read schema parsing and cost described in `history-policy-codec-r27.md`. The private final wire is loaded from a fixed package resource whose hash is independently pinned by the fixed descriptor. Startup still checks descriptor/schema/policy/wire hashes, exact full logical policy equality, schema validation and all catalog/policy/schema pins. Neither schema nor wire can be replaced through configuration, database input or an exposed setter.

For each compact raw R, strict Unicode/UTF8 encoding and independent hash remain, followed by the trusted raw-digest comparison and complete equality with canonical wire W. Startup establishes S(W); the complete equality R=W establishes S(R). Digest equality alone does not establish this proof. Only the exact canonical bytes inherit the schema proof; alternate whitespace, duplicate/extra/missing fields, incorrect versions/pins and malformed Unicode remain rejected. The full legacy branch, generic comparison, graph and genesis readers keep their original behavior.

Both query and non-query readers now return directly after the unchanged complete comparison. The query path actually removes the `history.schema` primitive, its lambda, JSON tree construction, Unicode tree traversal, serialization, validator reparsing and field validation. It does not lower the price of work that still runs. Startup schema validation remains in the constructor.

Canonical query cost: dispatch/guards/aliases/owner handling 32 + strict encode 304 + independent hash 304 + raw digest comparison 64 + complete wire comparison 304 = 1008. The removed tree pipeline was 6*304=1824 operations per read. This local cost is not a prediction of any complete business query. Complete legacy snapshots still cost 32+n.

The outer owner remains 4096+32n, acquired before the view/closures, and the nested encoder remains 128+3n. Nothing reduces these reservations. The helper returns and its view/closures expire before outer finally releases the owner, on normal and exceptional exits. SQL raw/checked-history owners, logical policy digest and all dynamic authorization/SQL-source/charset/locks/live/fence checks retain their original lifetimes and charges. Runtime/Error cleanup follows the existing finally; no new Error injection is claimed.

Targeted checks cover each fresh raw's encode/hash/full comparison, 1007/1008/1009 available operations, first-failure identity, scratch refusal and release, compact tampering on both reader routes, startup resource rejection, complete legacy comparison and ordinary/eventHistory consumers. Exact verification commands, class/JAR identities and one execution of each allowed private business scenario accompany the issue delivery. Previous 104 tests and historical matrices are not rerun or accumulated into this checkpoint.
