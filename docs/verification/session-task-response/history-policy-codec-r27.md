# v5 history immutable policy storage codec

New v5 history rows use a 304-byte internal snapshot referencing the unchanged 2174-byte logical policy. `record_version=1`, `history_version=5`, the frozen task binding, catalog, public contracts and V23 remain unchanged. Existing complete v5 and v1–v4 rows are not converted. `binding_digest` and `step.session_binding_digest` continue to identify the complete logical policy, not the stored compact bytes.

`HistoryPolicyCodec` pins the exact package descriptor SHA256. Its fixed local schema, full policy and canonical wire resources each have separate byte hashes; startup compares the complete policy resource to the original `SessionContracts.binding()` UTF8 bytes. No resource path comes from the database, configuration or network. The schema does not contain its own hash. Each compact raw independently undergoes REPORT UTF8 encoding/hash, trusted wire-digest comparison, exact wire equality and strict schema validation. Full-policy snapshots retain their exact full comparison reader. Missing pins/version, relabels, extra/duplicate keys, malformed Unicode and alternate raw bytes fail closed. No SQL raw is replaced or content-addressed proof reused.

Consumers: `MapperSessionHistoryStorage.insert` selects the new database wire while hashing the original logical policy. `MapperSessionHistoryProofs.matchesSnapshot` covers both ordinary and eventHistory sources through the shared history service. `MapperSessionHistoryRetentions.matchesSnapshot` covers both retention reads. Generic `matches`/equals retain their previous meaning. Scope/lineage/read/search/trace and step bindings consume history through these proof services and the unchanged logical digest; they do not publish a database snapshot body. SQL-source/charset, fresh size/raw, four simultaneous raw owners/fifth fallback, tenant/Work/query/token/connection/locks and terminal live/fence checks remain at their original call sites. `SessionCheckedHistories` retains the actual raw and the separate logical policy; no new authority cache is introduced. Metadata and cleanup still use actual SQL storage lengths, including the compact raw; there is no expanded database-string copy to hide.

New costs (in addition to unchanged surrounding routes): writer resource selection/handoff 2 operations; reader dispatch/guards/aliases/owner setup/cleanup 32; strict encoding n, hash n, raw-digest comparison 64, canonical wire comparison max(n,304), schema work 6n (strict parse/Unicode, serialization, validator parse and field checks). Thus canonical compact validation requests 2832 operations; the complete-snapshot branch requests 32+n. These are actual per-call prepayments, not deductions from an old group total. Runtime descriptor parsing is unnecessary: the package pin table is immutable and validated at startup.

Owner: reserve 4096+32n on the codec in this query before allocating the view/parser/schema temporaries; the nested strict encoder reserves 128+3n before its byte buffer. The helper returns before outer owner release so view/tree/closures have expired, including RuntimeException/Error exits. The existing SQL raw, proof rows, original policy aliases, generated graph and metadata bootstrap owners retain their full previous accounting. The immutable policy/wire stay package-owned; no per-read policy expansion/copy is allocated. Query limits/units and first failure handling are unchanged. N−1/N/N+1 operation and scratch refusal tests assert releases; malformed encoding also exercises nested finally release.

Validation records and exact source/JAR identities accompany the issue delivery. Tests cover legacy/full/new/mixed raw representations, independent repeated raw validation, descriptor/schema/policy/wire missing or tampered at startup, wrong pins/relabels/extra/duplicate fields/Unicode, logical-vs-raw digest separation, storage mapper arguments and generic equals, service version/missing/expired behavior and budget/first-error cleanup. The retention fixture now invokes the newly added default port method, preserving its original call-order assertions.

These targeted checks do not prove the full A12, nine-node one-query path, M2 all exits or real network/ACK. Existing two business probes are bounded to one run each after code, targeted verification and artifact are saved remotely. On continued failure, preserve the exact first fault and stop; do not add another representation or tune unrelated primitives. No CI, deployment, paid calls or shared database is part of this change.
