# Internal lineage graph storage codecs

The 2026-10-30 XIAO-126 PM decision authorizes this internal representation extension. It does not amend the frozen v5 catalog, task binding, public API, genesis-v1 bytes, or V23 migration. `task_session_lineage.record_version` and `Stored.version` stay 1. New graph JSON uses version 2 and the fixed `jimu.lineage.graph.refs.v2` codec; existing graph JSON remains version 1.

The immutable trust root is `LineageGraphCodecs.DESCRIPTOR_SHA256`, currently `3dec462a8d689ce99ab4d8f94eb78e557821aea0da148425fd2ca18a8eb809e2`. It checks the exact bytes of `session/storage/lineage-graph-codecs-v1.json`. That descriptor binds the only permitted schema path and schema SHA256 `de51a3b1d939e071df3a467b098f18d63e59a8104d50e9cd23956b8c623e6f70`, plus the `fresh-standalone-genesis-v1` semantics. Missing or modified descriptor/schema bytes fail construction. No raw, database value, configuration or network URL selects a schema. Each v2 raw carries both codec ID and schema hash; the existing whole-raw digest covers them and every ordered reference.

## Production consumers and source verification

`MapperSessionLineageRecords.graph(Graph)` is the only production graph writer. It now uses `storageGraph`; insertion still writes the complete genesis and graph raw, independent lengths/digests and structure version in the original transaction. No row conversion occurs. `graph(Graph)` and `graph(String)` in the wire contracts remain complete legacy graph-v1 serialization/deserialization. A pure string v2 cannot supply standalone sources and is rejected; callers with original source context use `matchGraph` instead.

`SessionLineageServiceImpl.validate` independently reads the current tenant-scoped source facts and rows and checks raw lengths, hashes, state, genesis schema, admission, authority, binding and parent edges. It then supplies the sorted exact caller/source node list to `MapperSessionLineageRecords.matchGraph`. No digest lookup replaces a fresh standalone read. The matcher supports both codecs in one pass, including arbitrary object-field order, strict JSON string escaping, duplicate/unknown field rejection and the frozen numeric validator. Version 1 requires all embedded snapshots and compares their full decoded text. Version 2 requires both exact pins and forbids snapshots. Every graph in a mixed set is matched independently. Missing/extra/duplicate/reordered references fail comparison. Trace/observe and recovery verification consume the resulting nodes with the real standalone snapshot bodies; no empty bodies are invented.

`MapperSessionHistoryRetentions.contents` treats both raws as retained content and does not decode them. `SessionQueryWork` retains exact created rows and verified graph proof in the existing Work/query/token lifecycle; it does not interpret raw codec versions. The scope/slot paths consume the verified proof and original graph digest. The source and transaction live/fence gates are unchanged. External trace output is still the original output schema; an internal v2 raw is never returned as graph-v1. The test-only typed output and prior compact schema candidate remain test-only.

## Costs and ownership

The new wire collection workspace reserves `32768 + 4096 + 512*N` scratch before map/list allocation: maximum resulting raw string, collection/alias workspace, and nodes. Creation and eventual collection cleanup prepay `12 + 7*N` operations; handoff prepays another 3, with the production receiver charging its four owner/alias actions. Existing serializer, copy, UTF-8 encoding and hash primitives execute against the actual compact raw; they are not rebated as a group. Actual header, codec, pin and reference characters are parsed and compared by the matcher. Numeric parsing/schema validation is still individually metered. The newly explicit scalar/source validation, codec field decisions and final shape checks also charge operations.

The matcher reserves its 4096-byte workspace before scalar regex validation or parser allocation, and retains separate numeric workspace while validating a token. The new writer keeps its output reserved through matching and invokes the receiver before refund. The receiver reserves `128 + 2*raw.length` on `generatedGraphOwner` and the raw-view map entry before retaining the returned reference. `withProof` clears the map and drops generated references before releasing these owners. Collection cleanup was prepaid and does not throw a new budget exception over a prior RuntimeException or Error. New and old source copies still coexist and are charged through the existing row/proof owners. This does not resolve the previously documented general facade/meter/JVM/native/socket A12 gaps.

Only eliminated embedded snapshot serialization, copying, escaping and parsing disappear; standalone genesis validation and the source raw/hash/owner paths remain. Limits stay 256 ResultSets, one absolute 2 seconds, 1 MiB scratch and 65536 operations. There is no G-group subtraction, counter reset, query split or new schema-path override.

## Necessary verification scope

`LineageStorageCodecTest` checks legacy and v2 matching, fixed packaged pins, missing/tampered resources, wrong/missing pin/version/codec, relabelled payloads, mixed node shapes, duplicate fields, exact ordered sets, changed fresh digests, owner handoff, RuntimeException/Error cleanup, scratch rejection and N-1/N/N+1 operation boundaries. `SessionLineageServiceTest` includes mixed persisted codecs, fresh row reads, missing sources, changed standalone bytes, PURGED, tenant and authority changes. `LineageRawViewTest` retains the affected legacy numeric/grammar and raw boundary differential checks. `QueryResultsFailureTest` supplies the necessary original first-slot, Error, cause/SQLState/suppressed and cursor-release regression. Prior codec precondition tests and the old success matrix need not be rerun.

Business evidence, exact final SHA/tree/JAR, command exits and remaining acceptance gaps are delivered separately. Passing these targeted tests is not full A12, the nine-node single-query budget, M2/three-trace/exits, a new independent database fence, real network R1/R2 or client ACK acceptance. No CI, deployment or shared database change is included.
