# Captured session event read provenance

ADR-0013 is accepted only for `read-receipt-sources-v1`, as decided in XIAO-54 comment `01a166ed-74fb-7321-9dce-1f0e5419d460` on 2026-10-23. This batch verifies the actual public events returned by a successful model read and the direct read receipts that reference them. It does not infer model causality or backfill old history. `replacement_policy=unsupported` is explicit. Surface and replacement chains remain undelivered; acceptance of this batch does not mean full G22/T46 compatibility. Their production behavior requires separate scope.

Enable `jimu.session-event-read.enabled`, `jimu.session-event-search.enabled`, and `jimu.session-event-trace.enabled` explicitly (all default off). Admit exactly `["session_event_read","session_event_search","session_event_trace"]` in order, with no resources/images and the existing trusted loopback, explicit paid=false whole-request proof. The stored binding is `local-session-event-trace-v3`; install read@0.3.0, search@0.2.0 and trace@0.1.0 with the output digests in `session/v3/catalog-v3.json`. Installation changes revoke tasks pinned to another version/epoch. The current single-version installation model is retained.

V21 extends the named V20 version checks and adds read provenance columns and original trace slot bindings. No V1–V20 migration, v1/v2 resource, or frozen baseline is changed. Old binaries reject schema21 before readiness. Rollback uses a binary that understands21 with flags off; no downgrade or history deletion. The grants generator only emits SQL and now includes the trace binding table.

M1 freezes one prefix for all slots. M2 binds trace input, target, upper sequence and task binding to the original slot. A successful model read captures actual returned row seq/digest pairs in the same transaction as output, outcome, once-only tool consumption, reliable receipts and native read receipt. Failed reads capture `[]`; other events always have empty sources. Owner reads, search and trace create no native receipts. Read sources are a body copy charged to history quota and removed on safe expiry.

Trace authorizes the task and current three pins, verifies the complete frozen prefix and flat read source proofs, and returns a public target summary and ascending direct source/reverse receipt sequences. It does not recursively inspect historical tool outputs. The captured target/window/slot, output bytes/digest and endpoint digests are checked independently. Limits remain128 candidates/2MiB events,180 edges,9 sources/20 derived,1024 source reads,8MiB proof/scratch,1,048,576 explicit operations,32KiB result and one absolute2 second query deadline. Limits fail; relationships are never silently truncated. Metadata and cleanup headroom may reject a task before the maximum model/tool counts; those are upper bounds, not promised available capacity.

`POST /api/tasks/{taskId}/session-history/trace` uses current SignedIdentity owner authorization before reading the body. JSON body is at most1024 UTF-8 bytes, contains only required `seq` and optional canonical `session_id`, and rejects duplicates, unknown fields, malformed Unicode, decimal/exponent/negative seq spellings and unsafe integers. Authorization, nonblocking body reading, connection and transaction share one absolute deadline. Responses use `Cache-Control: no-store`. Owner snapshots do not consume task budget or wake terminal tasks. Retained v3 owner history and cleanup continue with flags off; v1/v2 trace returns `SESSION_TRACE_UNAVAILABLE` after authorization.

Successful original trace replay rechecks authority, flags, pins, fence, original response/slot, stored receipt and output integrity, then returns the original bytes without observing later relations. Query faults roll back; uncertain commit uses the existing dedicated recovery signal. All source/query/output/checkpoint/event copies participate in the original7 day expiry and fixed-point accounting, including retained tombstones and reservation widths.

Development validation and actual T01–T11 coverage are recorded separately under `verification/XIAO-54/backend/`. No GitHub CI is run or awaited. Historical Windows verify failures, frozen ADR index differences and POSIX failures remain historical facts; targeted checks do not claim a full old matrix pass. Independent review, QA and product business acceptance remain required.
