# XIAO-40 R6：跨 JVM 的工作区操作绑定

文件层旧 SHA `0574e5eae3aaaa39e659438fc3d5281fd8284610` 在 `bind` 中只冻结内存观察。写意图的临时文件 fsync 后、rename 前退出，磁盘没有该操作的预期版本；同 ID 再次绑定会采用后来观察，覆盖竞争写入。R6 的问题是 CAS 身份丢失，内容/收据的原子 rename 本身没有损坏。

新准入 `SecureWorkspaceStore.bind` 在返回 FilePort 前，以现有安全目录句柄、同一跨进程锁及原子 fsync 状态替换持久保存 operation→观察快照。相同 ID 不能再次新准入，返回 `FS_OPERATION_MISMATCH`；宿主必须区分首次准入与恢复，不能用新准入作为恢复回退。身份和操作模式均由可信宿主管理，不进入模型参数。

跨 JVM 恢复使用 `resume`，仅读取原绑定及已持久调用收据，不从当前全局观察重建。没有原绑定、或首次调用的种类/参数尚未持久时，返回 `FS_BINDING_UNPROVEN`，即使没有竞争写入也不猜测原调用。写意图已持久而未完成时，仍以原 expected 做 CAS；竞争写入导致 `FS_STALE_VERSION`，无竞争可完成一次。已提交结果继续返回原收据，不覆盖后来内容。同 ID 改内容、路径或调用种类均拒绝。新准入在绑定 rename 前退出时没有可用端口；宿主恢复仍须用 resume，缺绑定明确拒绝。

文件状态格式从 1 升为 2，新增 bindings；旧格式没有足够绑定证据，明确返回 `FS_BINDING_UNPROVEN`，不自动迁移或重写旧字节。旧文件层尚未装配入业务任务，因此本阶段不提供猜测性恢复/迁移；运营者需要保留旧工作区取证，不能擦除记录后用原 ID 当作新操作。bindings 和既有操作/子收据分别限 100 条，任务实际工具总数仍由宿主的 20 次限制约束。状态/文件字节限额不变，数据库 V1–V5 和历史基线不变。

默认 WorkspaceIT 保留原文件层回归，增加真实独立 JVM 的十组对照：绑定 rename 前、绑定已持久、调用意图 rename 前、写意图已持久、内容/收据已提交，各含竞争写入和无竞争恢复。保留每组退出后、恢复前及最终原始状态、绑定/预期版本、参数变体、进程退出收据和内容/hash。首次调用意图尚未持久的保守拒绝属于明确恢复结果，不能声称该操作已成功或自动恢复。另有格式 1 不变字节拒绝对照。审查原始探针另在旧版精确 JAR 重放，和新版默认回归分开报告。

这是工作区文件层修复，没有公共 worker、模型 read/write/present、报告生产或下载的业务装配。R5 及默认完整 P2 保持回归；公共出口、真实模型/搜索付费请求关闭，PR 不合并，父任务保持 in_progress。最终 SHA 的定向和完整默认 verify 原始结果随交付证据提供，不把本说明的静态规则当作独立验收。
