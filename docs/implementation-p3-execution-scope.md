# Plus-only execution scope

V9 adds an operator-owned, immutable `(tenant_id, run_id)` scope and a nullable task digest. It creates no run, approval, scope or historical task binding. V1–V8, baseline documents and frozen evaluation materials remain unchanged. A scope narrows the original plan; it neither increases balances nor unlocks B. Flash/Max allowances cannot be reassigned to Plus.

`ExecutionScopeOperator` is an explicit offline operator entry, not an HTTP endpoint, startup role or worker action. Invoke the packaged main through Boot `PropertiesLauncher` with a nonsecret JSON file containing `requirement` and `binding`. Supply the operator JDBC URL/user/password only through restricted process environment (`JIMU_OPERATOR_DB_URL`, `JIMU_OPERATOR_DB_USER`, `JIMU_OPERATOR_DB_PASSWORD`), never arguments or evidence. Keep that process separate from application/worker credentials. The JSON uses `ExecutionScopes.Requirement` and `ExecutionScopeBinding.Input`: exact instance/schema/tenant/run/approval, canonical scope, both complete final model snapshots, account evidence and operator actor. The output contains canonical scope, digest and original binding timestamp/actor. No placeholder digest or incomplete account fact is installable. This delivery does not run this tool on the persistent project database.

The original read-only provisioning receipt and restricted `jimu.execution-scope.requirement` route the managed tenant before model selection. Both must agree with server UUID, current database, original approval, plan and materials. New scope binding requires the existing OPEN run and a reconciled dispatch/cost-reservation history; it never creates or resets a budget. Identical retry returns the original row; different content conflicts. Account evidence is supplied through the trusted operator channel; it is not independently discovered from a model or accepted from task JSON. Local test scopes are restricted to explicit test mode, trusted-local transport and literal loopback. The production operator constructor has no test-mode bypass.

A durable scope also marks its tenant as managed when the receipt row/table, requirement and plan selection are jointly absent. New routing uses an unambiguous persisted run; ambiguous authority refuses, while a known task retains its original run. Missing authority then refuses before task insertion instead of downgrading to an unpaid unscoped task. Unrelated ordinary tenants remain independent. Scope-table read failures are unavailable, never an ordinary-mode fallback.

The operator binder and runtime registry share pure full `ModelSnapshot` structural validation (version, adapter, URL, credentials reference, timeouts, capabilities, output/input and pricing bounds). Binding still applies the frozen plan, account facts and exact pins afterward. This validation neither resolves credential values nor checks/enables paid dispatch. Invalid structure is refused before the immutable scope INSERT, including a recalculated pin; a legal closed production profile can bind with an unavailable credential reference.

The binding response also includes `ledgerReadback` and `ledgerReadbackDigest`: deterministic current task/dispatch/reservation rows, including pending and unknown states, without goals or credentials. This is the current transactional readback, separate from the immutable first binding receipt. Initial binding rejects inconsistent tenant/task/run counts or costs and unproven dispatch/config/reservation linkage; it does not require a zero historical balance or invent replacement usage.

Admission takes run → tenant budget → task → child locks. A canonical scope and the complete pinned model digest are checked before task creation, claims, cached checkpoints, model/tool/workspace admission, report staging/publication and finish. The profile digest includes Host, credential reference/version, transport, stream, capabilities, prices and output options. A claimed proof mismatch commits a shared STOPPED fact before throwing; a missing initial deployment scope returns unavailable without automatically stopping an empty run. Historical NULL task digests are never backfilled or executable. Original shared STOPPED/UNKNOWN checks still take precedence.

Settlement of an already admitted operation uses its task/dispatch/config/price evidence and valid fence, independently of current scope or model registry. Missing historical pricing proof retains unknown reservations and stops the run for reconciliation. A model response can record actual usage/audit facts under refused scope, but cannot mint executable invocation intents. `presentSucceeded` remains admission because it publishes; it cannot use the settlement exception. Already published downloads keep their original owner/tenant/revocation/expiry/hash rules without requiring a live profile or scope.

Application grants are schema SELECT plus an explicit business-table DML allowlist, generated by `tools/evaluation/application_grants.py`. Scope, provisioning receipt and Flyway history receive no application INSERT/UPDATE/DELETE. This generator emits SQL only and never connects. Existing deployed accounts require an explicit privilege review before rollout; the migration cannot revoke external grants.

`ExecutionScopeIT` runs `tools/p3_execution_scope_verify.py` in default verify: owned MySQL, real control/worker JVMs, local TLS, frozen files and substitute ordinary/SSE models. It collects raw HTTP bytes and canonical scope HEX, binding crash windows, rejection counters, recovery, historical settlements, publication/download and cleanup. R03 exercises each of the 15 admission APIs in its own OPEN run/task in ordinary and SSE modes, with valid checkpoint/model/tool snapshot controls before corruption. Each exact scope mismatch must commit STOPPED before any new quota, HTTP, tool or artifact, survive process exit and competing recovery workers, and retain prior fees. Those controls establish scope admission; APIs with later business preconditions use the existing real-worker successful report/recovery paths as their end-to-end positive evidence. Direct host settlement injections are identified separately from actual provider protocol parsing. These tests do not establish real Qwen quality, account entitlement, production TLS deployment or P3 acceptance.

During this stage the unchanged HTTPS slow-drip cancellation test failed once (expected cancellation, normal return; its XML reported a negative elapsed duration). The exact historical clock change was not captured. The reader now also fixes its admitted remaining duration against monotonic elapsed time, so a later wall-clock rollback cannot extend that duration. A package-private admission-clock seam tests that boundary without changing the host clock. The original cancellation assertions and URL/IP/TLS policy remain in place; scope storage read failures explicitly return unavailable instead of authorizing execution or inventing a persisted integrity finding.

Future installation must first stop/exclude old worker binaries, verify quiescence, apply V9 with the migration identity, confirm SELECT-only metadata permissions, and explicitly bind a final scope only after account facts are complete. Old binaries reject the newer strict schema; rollback keeps execution closed and retains all tables, bindings and fees. This delivery performs none of those deployment actions. The delivered persistent database and unique ledger are retained, real model/search calls and production public egress remain closed, and B remains locked.
