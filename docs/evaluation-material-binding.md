Closed evaluation material admission
===================================

The two proposed plans remain disabled. Their budgets do not authorize paid dispatch.
Only the existing explicitly local test transport can exercise their runtime checks.

V8 binds host-loaded frozen materials to each new task. The loader verifies the common
manifest against the selected plan, then the referenced goal, request, source projection,
tool definitions and W4 draft bytes. Task acceptance compares the actual goal and fixes
the material snapshot, digest and expanded host-system digest. Sample labels and caller
hashes cannot establish a binding. Historical plan tasks without this evidence refuse;
the migration never infers or backfills their materials.

The worker inspects the initial target through SecureWorkspaceStore's native locked
directory boundary. This read-only host inspection does not grant a model observation.
W1–W3 require absence; W4 requires the frozen draft's actual hash/size and a positive
store version. The first receipt is durable before model preparation. Recovery compares
it, never replaces it. After a confirmed write, the original receipt and original model
read remain authoritative. Unknown file outcomes retain the existing refusal policy.
W4 provisioning uses the trusted FilePort before starting the worker; the test-only
EvaluationWorkspaceMain demonstrates this and is absent from the product JAR.

Every complete model body is checked before checkpoint reuse and again before model
quota/reservation: actual system text, goal, tool descriptions/Schema and fetched outputs
in history. For an existing step N, checkpoint reuse and dispatch reconstruct the exact
assistant/tool prefix through N-1 from persisted response and invocation facts. Preparing
a new step includes its completed predecessor. The comparison checks every assistant
content/call, provider ID, function, exact argument bytes, invocation input/output digest,
successful result and order; missing, repeated, reordered or rolled-back history refuses
before a new allowance or reservation. A step's own tools may already have committed:
its original request correctly excludes those results. Missing historical proof is never
backfilled. This uses existing records without changing migration bytes.

Tool admission restricts source URLs and task-relative target to the frozen
sample before tool quota. A write also requires the task's own successful model read.
The canonical model-visible fetch output must match; raw page bytes are supporting
evidence rather than a replacement for that check. A confirmed nonmatching fetch is
still recorded and settled. Its result and persistent shared STOPPED are one fenced
transaction, followed by rejection outside the transaction. Other material admission
refusals also commit STOPPED before surfacing the error, so a crash before task failure
cannot undo the stop. Further admissions and
publication honor the existing run lock. Known charges and UNKNOWN liabilities remain.

The default verify runs the original full plan matrices separately from material
regressions. These use actual worker JVMs, MySQL, local TLS serving frozen raw sources,
and substitute JSON/SSE models. They exercise arbitrary goals, source URL/body changes,
Schema/description/system/goal/cache changes, real kill/restart, and W4 missing/changed
drafts versus frozen positives. These checks establish material binding, not model
quality, C1/B qualification, real provider billing, or P3 acceptance. Synthetic quality
predecessors in negative W4 tests are explicitly labelled SQL fixtures.

EvaluationHistoryIT additionally exercises JSON/SSE history faults after actual worker
exit and control/worker restart. These are private database fault injections, not evidence
of a naturally occurring truncation or ordinary API access to snapshots. Positive recovery
includes a completed own-step tool, a partially completed multi-tool response and a fully
prepared next step, with actual report production and owner download. The argument-change
case explicitly seeds a prior HELD_UNKNOWN reservation to verify that refusal retains it;
it does not claim an actual provider produced that synthetic liability.

New model request/response bodies are captured as binary at the HTTP listener. Step
snapshots are exported as SQL HEX, decoded without a terminal charset, and paired with
complete UTF-8 body hashes. The mysql client also explicitly uses utf8mb4. Old corrupted
TSV exports stay unchanged; new captures do not retroactively prove missing old bytes.
HTTP capture indices are independent of SSE tool-call indices. Each produced response
records its own hash and size, and the default plan, material and history regressions
verify every request/response file against its own call record. Earlier captures affected
by the SSE index overwrite remain unchanged with their response gaps listed separately.
