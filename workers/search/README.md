# Optional native search bundle

Linux x86_64, non-root, private POSIX storage and working unprivileged user/mount/PID/network namespaces are required. The application never downloads native code. `rg` is the exact static binary from `@vscode/ripgrep-linux-x64@1.18.0`, SHA256 `193906679498de4d939345b937fa24e0e69a03c244bd70c859f5e41232713f21`. `bwrap` is Ubuntu `0.9.0-1ubuntu0.3`, SHA256 `e318903862396f96de3df57264e0158682b952fd3fb53ac23d876413e7b30f71`, dynamically linked to the host libc/libcap. The launcher is built from the adjacent C source; its local build digest must be configured explicitly.

`source-inputs.json` records exact local input SHA256 and retrieval locations. Obtain these inputs during bundle preparation, verify them, then run offline:

```text
python3 tools/native_bundle.py --inputs /operator/native-inputs --output /operator/new-bundle --cc cc
```

The output directory must not exist. `--cc-arg` permits an operator's private sysroot/toolchain flags, each as a separate argument. No shell is used. The script copies binaries, notices, conservative SBOM, corresponding source archives (including the Ubuntu patches), and a compiler/build/dynamic-dependency receipt. Build output hashes are toolchain dependent; this is a reproducible preparation recipe, not a claim of bit-identical builds across compilers. Do not replace a running bundle in place. Host libc/libcap must be independently maintained; they are prerequisites and are not copied into the namespace or redistributed by this script. Their test-host copyright texts are included for traceability.

The npm binary reports ripgrep 15.0.0 (`3a612f88b8`) with static PCRE2 10.45. The available vendor `v15.0.0` archive has a different digest (`f2ee496a39139b8d9ad9408081217a55f1382cef4950100565d147d247364856`); it is not substituted for the pinned npm binary or claimed to be byte-identical. The corresponding vendor recipe at Microsoft ripgrep-prebuilt `5c302c331f59f578fd90e024a8f374012c40e8b4` uses ripgrep `3a612f88b8`, Rust 1.88.0, static PCRE2 and the musl target. The published npm tag alone is insufficient provenance: the later vscode-ripgrep tag points at a different recipe. `sbom.cdx.json` includes every locked crate, including build/test/other-target packages, plus vendored PCRE2/jemalloc, Rust standard-library/libunwind and musl notices. This deliberately overinclusive source inventory is not a vendor attestation of each linked feature or of an exact npm rebuild. No claim is made that npm's MIT license covers the static closure.

Retain `THIRD_PARTY_NOTICES.txt`, SBOM and all applicable notices with redistributed binaries. Keep the matching bubblewrap original source and Ubuntu patch archive alongside the bundle; they are included by the preparation script. Bubblewrap is LGPL-2.0-or-later and remains a separate executable; its corresponding source/build scripts and replacement rights must remain available. PCRE2 and jemalloc retain their own BSD notices. DeepSeek Harness MIT attribution is in `docs/verification/XIAO-43/Harness-LICENSE.txt`; include it with redistribution. Jimu does not enable rg PCRE2 mode.

The host supplies a length-framed spec to a single C launcher. It opens every ancestor without following links and checks dev/inode; restores exact persisted nanosecond mtimes via pinned ordinary files; fsyncs `launch.json` before any fork; and gates namespace execution until Java has saved all process identities. Only projection and fixed rg descriptors enter the empty mount root. Startup ambiguity stays unproven. No receipt, unreadable proc, or Java exit is treated as proof that a launched namespace stopped. CPU 10/11s, address space 512MiB, nofile 64, core 0; the Java wall clock and existing supervisor enforce cancellation/deadlines and collect drainers before STOPPED.

The QA-01 launcher adds only `--probe-absent <positive-pid>`: as the same non-root identity, invoke `kill(pid, 0)` without sending a signal; exit 0 only for ESRCH, 1 for a live PID, 125 for any unproven error (including EPERM). It does not fork, open task data or run a supplied command. Java bounds and collects this synchronous probe and verifies the launcher digest before every invocation. This supplies independent kernel evidence when proc hides a live PID. Rebuild into a fresh bundle and update the configured launcher hash; rg/bwrap and their provenance/license limitations remain unchanged. No production enablement or external distribution is approved by this correction.

R1 binds that evidence to its PID coordinate system. Every launch/started process identity now includes `observerPidNamespace`, captured by the parent launcher alongside boot ID, target start ticks and target own namespace. Java validates the receipt's observer boot/namespace before any probe, identity-change conclusion or signal. The init's own namespace can legitimately differ from the observer's. Old receipts lacking the observer and receipts from other boot/namespaces remain unproven; they are never automatically rebound to the restoring service.
